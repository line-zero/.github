# Contributing

Keep changes focused, reviewable, and easy to understand.

## Working conventions

- Use short-lived branches from the repository's default branch.
- Open a pull request for meaningful changes.
- Keep unrelated changes in separate pull requests.
- Add tests when they materially reduce regression risk.
- Update documentation when behavior, configuration, or operational steps change.
- Never commit secrets, credentials, customer data, production exports, or sensitive internal information.
- Prefer simple implementations over unnecessary abstraction.

## Commits and pull requests

Use clear commit messages and explain the reason for a change in the pull request, not just what files changed.

Call out migrations, deployment steps, breaking changes, security implications, or operational risk explicitly.
